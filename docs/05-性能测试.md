# 05-性能测试

本页只描述当前仓库里真实存在的 benchmark 目标、参数和结果声明，不再保留无法回溯到源码的历史 QPS 表。

## 当前结果声明

- 本次文档修复没有重跑完整 benchmark 负载
- 因此本页只保留“当前源码可复现的方法”和“输出字段说明”
- 任何具体 QPS/延迟数字，都应当以你本次运行 `B1-redis_client_bench` / `B2-connection_pool_bench` 的控制台输出为准

## 构建前提

- CMake：`3.20+`
- 编译标准：`C++23`
- 构建开关：`BUILD_BENCHMARKS=ON`
- 依赖：`OpenSSL`、`spdlog`、`galay-kernel`、`galay-utils`
- 运行环境：至少一个可访问的 Redis 实例；建议 `Release` 或 `RelWithDebInfo`

```bash
cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_BENCHMARKS=ON \
  -DBUILD_TESTS=OFF \
  -DBUILD_EXAMPLES=OFF
cmake --build build --parallel --target B1-redis_client_bench B2-connection_pool_bench
```

## 目标与源码

| 目标 | 源文件 | 关注点 |
|---|---|---|
| `B1-redis_client_bench` | `benchmark/B1-redis_client_bench.cc` | 单连接/normal-batch/pipeline 模式吞吐与延迟 |
| `B2-connection_pool_bench` | `benchmark/B2-connection_pool_bench.cc` | 连接池 worker 并发吞吐与池统计 |

旧文档中的 `B1-RedisClientBench`、`B2-ConnectionPoolBench` 不是当前仓库里的真实目标名。

当前 benchmark 目标仍然是 TCP 路径：

- `B1` 使用 `RedisClient`
- `B2` 使用 `RedisConnectionPool`
- 仓库里还没有单独的 `RedissClient` / `RedissConnectionPool` benchmark 目标

## `B1-redis_client_bench`

### 当前 CLI

源码中的 usage 为：

```bash
./build/benchmark/B1-redis_client_bench \
  [-h host] [-p port] [-c clients] [-n operations] \
  [-m normal|normal-batch|pipeline] [-b batch_size] \
  [--timeout-ms -1|N] [--buffer-size bytes] [--track-alloc] [-q]
```

### 推荐复现命令

普通模式：

```bash
./build/benchmark/B1-redis_client_bench \
  -h 127.0.0.1 -p 6379 -c 10 -n 1000 -m normal -q
```

pipeline 模式：

```bash
./build/benchmark/B1-redis_client_bench \
  -h 127.0.0.1 -p 6379 -c 10 -n 50000 -m pipeline -b 100 -q
```

normal-batch 模式：

```bash
./build/benchmark/B1-redis_client_bench \
  -h 127.0.0.1 -p 6379 -c 10 -n 50000 -m normal-batch -b 100 -q
```

### 当前输出字段

`B1` 的控制台输出分两段：

- 启动摘要
  - `Host`
  - `Clients`
  - `Operations per client`
  - `Mode`
  - `Batch size`（仅当 mode 为 `pipeline` 或 `normal-batch`）
  - `Timeout (ms)`
  - `Client buffer size`
  - `Allocation tracking`
  - `Planned operations`
    - `pipeline`：`clients * operations`
    - `normal` / `normal-batch`：`clients * operations * 2`
- 结果段
  - `Finished`
  - `Completed clients`
  - `Duration`
  - `Success`
  - `Error`
  - `Timeout`
  - `Ops/sec`（仅当 `Duration > 0`）
  - `Requests measured`（仅当收集到 latency 样本）
  - `Request latency p50 (us)`、`Request latency p99 (us)`（仅当收集到 latency 样本）
  - `Success rate`（仅当 `Success + Error + Timeout > 0`）
  - `Alloc calls/op`、`Alloc bytes/op`（仅当 `--track-alloc` 且总样本数大于 0）

## `B2-connection_pool_bench`

### 当前 CLI

源码中的 usage 为：

```bash
./build/benchmark/B2-connection_pool_bench \
  [-h host] [-p port] [-c workers] [-n operations] \
  [-m min_connections] [-x max_connections] [-q]
```

### 推荐复现命令

```bash
./build/benchmark/B2-connection_pool_bench \
  -h 127.0.0.1 -p 6379 -c 20 -n 300 -m 4 -x 20 -q
```

### 当前输出字段

`B2` 的控制台输出也分两段：

- 启动摘要
  - `Host`
  - `Workers`
  - `Operations per worker`
  - `Pool min/max`
  - `Planned operations`（固定按 `workers * operations * 2` 打印）
- 结果段
  - `Finished`
  - `Duration`
  - `Success`
  - `Error`
  - `Timeout`
  - `Ops/sec`（仅当 `Duration > 0`）
  - `Success rate`（仅当 `Success + Error + Timeout > 0`）
  - `Pool stats`
    - `total_connections`
    - `available_connections`
    - `active_connections`
    - `total_acquired`
    - `total_released`
    - `peak_active_connections`

## 方法学建议

如果你需要把结果写回团队文档，建议同时记录：

- Redis 版本
- 部署方式：本地单机 / Docker / 远程服务
- CPU、内存、OS
- 构建类型：`Release` / `RelWithDebInfo`
- 客户端参数：`clients` / `workers`、`operations`、`batch_size`
- timeout 与 buffer size

## benchmark caveats

- `--track-alloc` 会改变开销，不适合与未开启统计的结果混合比较
- `B1` 的 `pipeline` 与 `normal-batch` 代表两种不同工作负载，不能直接按同一基数解读
- `B2` 统计的是连接池 worker 层吞吐，不是单条 Redis 命令的纯网络极限
- 当前仓库没有自动把 benchmark 输出写回 Markdown；你需要自己保存原始终端输出
